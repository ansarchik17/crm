# Тест OpenAI Realtime

Добавлен отдельный режим `/realtime`: прямой разговор голосом через WebRTC.
В этой ветке не используются Alem STT или браузерный SpeechSynthesis.
Основной интерфейс теперь EspoCRM на localhost:8080; `/` голосового сервиса
перенаправляет в него. На `/voice` обычный последовательный диалог: Alem STT → текстовый OpenAI →
SpeechSynthesis; для локальной проверки доступен `LLM_MODE=demo`.

## Настройка

В существующий локальный `.env` добавьте `OPENAI_API_KEY=ваш_ключ`.
Не заменяйте файл целиком: в нём уже есть настройки Alem. Ключ не нужно отправлять
в чат или вводить на веб-странице. Этот же серверный ключ используется обычной
текстовой моделью в режиме `LLM_MODE=openai`. Настройки `OPENAI_MODEL` и
`OPENAI_REASONING_EFFORT` не меняют Realtime-модель. Затем перезапустите Uvicorn.

Необязательные настройки (значения по умолчанию):

```dotenv
OPENAI_REALTIME_MODEL=gpt-realtime-2.1
OPENAI_REALTIME_VOICE=marin
OPENAI_REALTIME_REASONING=minimal
OPENAI_REALTIME_SILENCE_MS=300
OPENAI_REALTIME_TIMEOUT_SECONDS=25
```

Модель взята из актуального руководства Realtime. Доступ конкретного аккаунта
и совместимость полной конфигурации необходимо проверить живым подключением.
API тарифицируется отдельно; наличие ключа не доказывает наличие квоты.
Параметр reasoning передаётся только для семейства `gpt-realtime-2`.

Откройте http://127.0.0.1:8001/realtime, нажмите «Начать разговор» и разрешите
микрофон. Реплики отправляются автоматически после настроенной паузы, по
умолчанию 300 мс. Допустимый диапазон локальной настройки — 100–1000 мс.
Меньшая пауза раньше запускает ответ, но может принять паузу внутри предложения
за конец реплики. Если речь разделяется неправильно, увеличьте значение,
например до 500 мс, и перезапустите сервер.
«Завершить» закрывает WebRTC и останавливает микрофон. Можно отключить только
микрофон и слушать текущий ответ. Через 5 минут интерфейс автоматически завершает
разговор. Это ограничение клиентского теста, не серверная квота или лимит расходов.
В текущем локальном сеансе порт 8000 занят другим проектом; CRM запускается на
8001, если порт свободен.

## Как устроено

- Браузер создаёт SDP offer и POST `/realtime/calls` с `application/sdp`.
- FastAPI отправляет multipart `sdp` и `session` на OpenAI `/v1/realtime/calls`.
  Постоянный ключ используется только на сервере; браузер получает SDP answer.
- Аудио идёт по WebRTC прямо между браузером и OpenAI. Data channel передаёт
  события, расшифровку и статистику. Никакого ожидания полного WAV-файла нет.
- Настроен `server_vad`, `create_response=true`, `interrupt_response=true`.
  При перебивании очисткой звукового буфера управляет OpenAI WebRTC.
- Входная расшифровка `gpt-transcribe` работает асинхронно только для экрана;
  модель слышит аудио напрямую. Расшифровка может отличаться от воспринятой речи
  и добавляет отдельную обработку/расход. Её завершения ответ не ждёт.
- Ответы озвучивает OpenAI голосом `marin`. Лимит — 1024 выходных токена на ответ.
- Настройки `/realtime/config` показывают наличие ключа, модель, голос и VAD-паузу;
  endpoint не выполняет живую проверку доступа.

Локальный endpoint отклоняет чужие Origin/Host и нелокальный адрес клиента,
неправильный Content-Type,
невалидный SDP и запросы больше 64 KiB; параллельные подключения сериализованы
с отказом 429. Ответы ошибок провайдера и ключи не выводятся. Это по-прежнему
локальный прототип без пользовательской авторизации; публичное развёртывание
не входит в текущую реализацию. Сервер не хранит аудио и тексты Realtime на диске.

## Честное сравнение скорости

«Отклик сервиса» — интервал между получением `input_audio_buffer.speech_stopped`
и `output_audio_buffer.started` для соответствующего ответа. Он **не включает**
настроенную паузу VAD (по умолчанию 300 мс) и время доставки/воспроизведения аудио. Это не полный
замер «последний звук клиента → первый звук помощника». Сравнивать это число
с `latency_ms` обычной текстовой модели OpenAI как одинаковые
метрики нельзя.

На странице показаны последний отклик, количество замеров, медиана и p95
методом nearest-rank: отсортированный элемент с номером `ceil(0.95 × n)`.
Статистика относится к текущему разговору. В неё входят ответы с начавшимся
аудиобуфером и `response.done: completed`; отменённые, ошибочные, неполные
и прерванные ответы исключаются. При последующем перебивании замер удаляется.
Эту статистику нужно дополнять числом ошибок и перебиваний при живом тесте:
она описывает только успешно завершённые ответы, а не все попытки.
При малой выборке p95 предварительный. Цель около 1 с до первого слышимого
звука требует отдельного живого измерения.

Используйте одинаковые вымышленные реплики: чистка с датой, вопрос о цене,
смена времени, перебивание, просьба подтвердить несуществующую запись.
Сравнивайте осмысленность ответов, лишние вопросы, правильность даты, способность
остановиться при перебивании и фактическую паузу на слух. Текст прерванного ответа
помечается: он мог прозвучать не полностью.

## Проверки

```sh
.venv/bin/python -m pytest -q
node --test tests/test_audio.mjs tests/test_realtime_events.mjs
```

На момент первоначального добавления: 46 Python-тестов и 8 Node-тестов прошли.
После настройки VAD и обработки поздних событий 13 октября: 65 Python-тестов
и 19 Node-тестов прошли. Проверены перенос настройки в multipart OpenAI,
границы параметра, статистика, отмены и защита нового ответа от старых событий.
HTTP-контракт проверен через MockTransport, обработка событий — синтетическими
событиями. В Chrome проверена страница без ключа: старт заблокирован с объяснением.
**На 13 октября 2026 `OPENAI_API_KEY` уже добавлен локально; живая проверка
Realtime ещё не завершена.** Обычная текстовая модель OpenAI и Alem STT уже
дали HTTP 200 на тестовом WAV; это не проверяет браузерный звук Realtime.
Наличие ключа само по себе не подтверждает доступ к Realtime-модели.
