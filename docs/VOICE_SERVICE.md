# VoiceCRM

> Исторический снимок README до перехода на EspoCRM 13 октября 2026.
> Основной интерфейс теперь на localhost:8080, голосовой тест — на 8001/voice.
> Актуальный запуск: [ESPOCRM.md](ESPOCRM.md). Статусы ниже относятся к прототипу.

Начало разработки голосового администратора: городской номер, до 30 внутренних
номеров, консультации, перевод сотрудникам, CRM, записи и анализ.

**Текущее состояние:** локальный прототип стоматологии с веб-страницей, записью
микрофона в WAV, файловым STT Alem, текстовыми ответами OpenAI и озвучиванием
голосами браузера. Для обычного диалога `/` выбран `LLM_MODE=openai`;
доступен также локальный `demo`. Интеграция Qwen, её настройки и ключ удалены
по просьбе пользователя. `OPENAI_API_KEY` добавлен локально; Alem STT и основной
диалог с OpenAI проверены реальными запросами — оба вернули HTTP 200.
Проверка звука браузера, записи микрофона и Realtime ещё не завершена.
Телефония, серверный TTS, CRM,
база знаний и аналитика ещё не реализованы. Название папки CRM не означает,
что здесь уже есть готовая CRM. Полный разбор: [docs/PROJECT.md](PROJECT.md).
План реализации заказа по этапам: [docs/ROADMAP.md](ROADMAP.md).

Для разработки подготовлена [команда из восьми агентов](../agents/README.md):
архитектура, голосовой backend, WebRTC, проверка скорости, CRM-интеграции,
телефония, аналитика и знания компании. Правила совместной работы — в
[AGENTS.md](../AGENTS.md), исходные профили — в `agents/profiles/`.

## Структура

```text
src/voicecrm/
  main.py        сборка приложения, тестовые страницы, /health
  config.py      настройки из .env
  errors.py      ProviderError без деталей провайдера
  dialogue/      STT, OpenAI/demo, промпт, сессии, OpenAI Realtime, HTTP-маршруты
  telephony/     Asterisk, SIP, внутренние номера, очереди — не начато
  crm/           интеграция с CRM — не начато
  analytics/     записи и AI-анализ — не начато
  static/        страницы / и /realtime
```

Настройка Alem STT: [docs/ALEM.md](ALEM.md).
Распознавание ранее проверено с подменой HTTP и с реальным API на локальном ключе.
Исторические замеры Qwen описаны в [docs/ALEM.md](ALEM.md); они не описывают
скорость новой модели OpenAI. Режим Qwen и его отдельный benchmark-скрипт удалены.

Добавлен отдельный тест **OpenAI Realtime (голос → голос)** на
http://127.0.0.1:8001/realtime. Он использует тот же `OPENAI_API_KEY`, что и
обычный текстовый диалог, но отдельную Realtime-модель.
Код и локальные проверки готовы; живая проверка ещё не завершена.
Настройка, устройство и ограничения: [docs/REALTIME.md](REALTIME.md).

## Тестовая стоматология

Для модели настроен сценарий администратора стоматологии: консультация, чистка,
лечение кариеса, удаление зуба, консультации по имплантации и брекетам.
Это учебные направления; реального прайса, клиники и расписания пока нет.
Помощник уточняет услугу, день и время, учитывает изменения пожеланий и сообщает,
что настоящая запись не создана. Медицинские назначения в сценарий не входят.

Ручная проверка выбранной модели на реальном API (6 запросов, возможна тарификация):

```sh
.venv/bin/python scripts/test_dental_dialogue.py
```

Скрипт использует две отдельные сессии, проверяет ответы на изменение дня,
вопрос о цене и попытку получить вымышленное подтверждение. Ответы нужно оценить
вручную; успешный HTTP-ответ сам по себе не означает корректный диалог.
После изменения системного промпта перезапустите уже работающий сервер.

## Запуск

Нужны Python 3.11+ и uv. Из папки проекта:

```sh
uv sync --locked
uv run uvicorn voicecrm.main:app --host 127.0.0.1 --port 8001
```

Если `.env` ещё нет, скопируйте `.env.example`; существующий файл не заменяйте.
Добавьте локальный ключ и настройки из раздела «Подключение OpenAI» ниже.
Без ключа сервер запускается, но OpenAI отмечен как не настроенный и AI-ответы
недоступны. После изменения `.env` перезапустите сервер.

Откройте **http://127.0.0.1:8001/** для голосового теста. Порт 8000 на этой машине
занят другим проектом; текущий CRM запускается на 8001, если порт свободен.

1. Нажмите «Говорить» и разрешите браузеру доступ к микрофону.
2. Произнесите реплику и нажмите «Закончить запись» (автоостановка через 29 секунд).
3. Страница передаст WAV в Alem STT, затем текст — в OpenAI в текущей сессии.
4. Ответ появится в переписке и будет озвучен выбранным голосом браузера.
   Если автоматическое воспроизведение не сработало, нажмите «Прослушать».

Страница отдельно показывает время STT и OpenAI. Общий счётчик заканчивается
на событии начала браузерного озвучивания `SpeechSynthesisUtterance.onstart`.
Он относится к обработке после отправки реплики и не включает длительность
записи микрофона. Проверка этого события с реальным звуком пока продолжается.

Можно писать текстом или загрузить поддерживаемый WAV. «Новый диалог» очищает
контекст. Для микрофона нужны localhost/HTTPS и браузер с AudioWorklet и записью
24 кГц; ошибка доступа не мешает текстовому режиму. Используйте вымышленные данные.
Голоса зависят от устройства; предпочтение отдаётся русскому локальному голосу.
Голоса «онлайн» могут отправлять текст своему поставщику. Отдельного TTS API-ключа
не требуется. Это диалог по очереди, не streaming: перебивания, телефонное аудио
и серверное создание озвученных файлов пока не реализованы. `/health` продолжает
возвращать `tts_connected=false`, поскольку серверного TTS нет.

Документация API: http://127.0.0.1:8001/docs. В режиме `demo` текстовые ответы
фиксированные и не требуют ключей; STT включается независимо. В текстовом демо
внешние запросы не нужны; это проверка сервиса, а не AI-консультация.

1. Выполните `POST /sessions`, скопируйте `session_id` из ответа.
2. Выполните `POST /sessions/{session_id}/messages` с телом
   `{"text":"Здравствуйте, хочу узнать об услуге"}`.
3. Отправьте вторую реплику с тем же идентификатором.
4. Завершите тест через `DELETE /sessions/{session_id}`.

## Подключение OpenAI

В существующем локальном `.env` задайте:

```dotenv
LLM_MODE=openai
OPENAI_MODEL=gpt-5.4-mini
OPENAI_REASONING_EFFORT=none
OPENAI_API_KEY=ВАШ_КЛЮЧ_OPENAI
```

Перезапустите сервер. Постоянный ключ остаётся на сервере и используется также
для `/realtime`. `OPENAI_MODEL` и `OPENAI_REASONING_EFFORT` относятся к обычному
текстовому диалогу; настройки `OPENAI_REALTIME_*` задаются отдельно.
На `/` OpenAI получает распознанный текст: STT остаётся Alem, а озвучивание —
SpeechSynthesis в браузере. Прямой голосовой режим находится на `/realtime`.
В текущем проекте ключ уже добавлен локально, реальный запрос основной модели
успешен. Проверка качества многошагового разговора и браузерного звука продолжается.
Запросы к API могут тарифицироваться.

Контракт запроса: [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).
Модель и поддержка `none`: [GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini).

Ключи храните только локально в `.env`; он исключён из Git. Сервис не сохраняет
тексты на диск и не выводит ответы провайдера при ошибке. В режиме OpenAI тексты
передаются OpenAI, при включённом STT аудио передаётся Alem.
Для проверки используйте вымышленные обращения.

## Проверки

```sh
uv run pytest -q
node --test tests/test_audio.mjs tests/test_realtime_events.mjs
```

Тесты не обращаются к платным API. Они проверяют контекст, разделение сессий,
удаление, ограничения, отказ провайдера и HTTP-контракт адаптера.

13 октября отдельно выполнена живая цепочка на WAV длительностью 11.0335 с:
Alem STT и OpenAI дали HTTP 200. Сумма длительностей двух HTTP-запросов —
7.79305 с в первой проверке и 6.480848 с в повторе. В повторной автоматизированной
цепочке полный интервал обработки составил 6.537 с, включая организацию вызовов
инструментом проверки. Эти числа не включают 11.0335 с записи и запуск
SpeechSynthesis в браузере. Повторялся тот же файл, возможен кэш; это малая выборка.
Подробные границы и раздельные измерения: [docs/HANDOFF.md](HANDOFF.md).

## Ограничения прототипа

- Только localhost, без авторизации; не публиковать в интернете.
- Один процесс: сессии в памяти, при перезапуске исчезают.
- До 100 сессий; ненужные удаляются вручную. До 20 реплик клиента на сессию.
- Один запрос на сессию одновременно; повтор получает 409.
- `/health` показывает состояние процесса, а не доступность внешнего AI.
- Инструкции модели не гарантируют достоверность ответов. До пилота нужны
  утверждённые знания, проверяемые действия и оценка качества.
- Замер `latency_ms` относится к текстовому ответу; это не задержка голосового диалога.

Следующий шаг для цели около одной секунды — живой тест `/realtime`:
качество пауз и перебиваний, время от конца речи до первого слышимого ответа.
Браузерный тест звука и микрофона обычного диалога `/` также требует завершения.
Серверное аудио для телефонии и CRM-интеграция остаются следующими этапами.
