# Alem.ai: распознавание речи и исторические замеры Qwen

В текущем приложении Alem используется для файлового STT. Текстовые ответы
выполняет OpenAI; доступен также локальный demo. Интеграция Qwen, её настройки,
ключ и отдельный benchmark-скрипт удалены 13 октября 2026 по просьбе пользователя.
Результаты прежних проверок сохранены в историческом разделе ниже.

Изучены публичные страницы [STT](https://doc.alem.ai/services/speech.html) и
[STT Kazakh](https://doc.alem.ai/services/speechkaz.html), включая изображения примеров.

## Параметры STT из документации

| Сервис | URL POST | model |
|---|---|---|
| STT | https://llm.alem.ai/v1/audio/transcriptions | speech-to-text |
| STT Kazakh | https://llm.alem.ai/v1/audio/transcriptions | speech-to-text-kk |

На доступах этого проекта живым запросом проверен `speech-to-text`.
`speech-to-text-kk` ранее вернул 403 и не используется в текущей конфигурации.

Авторизация — Bearer. STT отправляет multipart с полями `model`
и `file`. Общий STT-пример содержит `language=en`; казахский пример — без языка.
HTTP-клиент сам формирует multipart boundary. Ключи с изображений документации
не используются. Для подключения нужны ваши собственные доступы.

## Что пока неизвестно

В просмотренных страницах нет схемы ответа STT, протокола потокового STT,
лимитов файлов/параллелизма, тарифов или API синтеза речи. Упоминание микрофона
не подтверждает поддержку streaming. Поддержка русской речи и смешанных языков
проверяется на реальных примерах.

Адаптер STT ожидает JSON `{"text":"распознанная речь"}`; эта форма была принята
при успешной живой проверке проекта. Другой ответ вызывает явную ошибку.
Это проверка конкретного сценария, а не полная схема всех ответов Alem.
Реальные запросы и замеры от 28 сентября 2026 описаны ниже;
ключ STT хранится в локальном `.env`.

## Настройка Alem STT

Если `.env` отсутствует, скопируйте `.env.example`. Если уже существует —
добавьте настройки вручную, сохранив свои значения.

```dotenv
STT_ENABLED=true
STT_BASE_URL=https://llm.alem.ai/v1
STT_MODEL=speech-to-text
STT_API_KEY=ВАШ_КЛЮЧ_STT
STT_LANGUAGE=
```

STT настраивается независимо от текстовой модели. Для локального текстового demo
задайте `LLM_MODE=demo`; для AI-ответов используйте настройки OpenAI из README.
У Alem STT свой `STT_API_KEY`, отдельный от `OPENAI_API_KEY`.
Перезапустите приложение после изменения `.env`. Выбор казахской модели требует
отдельной проверки доступа аккаунта и качества распознавания.

## Проверка аудио

Локальный маршрут принимает **тело WAV-файла**, не multipart. Приложение само
собирает multipart для Alem. Для первого теста используйте короткую вымышленную
реплику. Ограничения нашего прототипа: PCM WAV, mono, 16 bit, 8/16/24/48 kHz,
до 30 секунд и 4 MiB. Это не заявленные лимиты или гарантии совместимости Alem.
Файлы не сохраняются на диск, но при включённом STT передаются провайдеру.

```sh
curl --fail-with-body http://127.0.0.1:8001/transcriptions \
  -H 'Content-Type: audio/wav' \
  --data-binary @speech.wav
```

Ожидаемый ответ нашего сервиса: `text`, `speech_detected`, `latency_ms`.
Пустая транскрипция даёт `speech_detected=false`. Неподдерживаемый WAV — 422,
превышение размера — 413, отключённый STT — 503, ошибка провайдера/схемы — 502.

Передайте полученный `text` в `POST /sessions/{session_id}/messages`, используя
ранее созданную сессию. Это два отдельных запроса для проверки каждого этапа;
на веб-странице `/` эти запросы выполняются последовательно автоматически:
Alem STT → текстовая модель OpenAI → SpeechSynthesis в браузере.
Серверного TTS пока нет.

Следующая проверка с доступами: измерить задержку и качество на нужных языках,
затем выбрать TTS. Для круглосуточного голосового
робота потребуется отдельная проверка потокового звука и телефонных кодеков.

## История: проверка задержки 28 сентября 2026

Ниже результаты удалённого режима Qwen. Они сохранены для истории и не
описывают текущую модель OpenAI. Скрипт `benchmark_qwen.py` удалён;
оставшийся benchmark задержки переписан под OpenAI и не повторяет эти замеры.
До перехода на OpenAI также изучалась [документация Qwen в Alem](https://doc.alem.ai/services/qwen36.html).

На доступах этого проекта проверены `qwen3-8` и `speech-to-text`.
Для коротких ответов голосового помощника тогда в локальном `.env` включили
`QWEN_ENABLE_THINKING=false`. Прежний адаптер передавал
`chat_template_kwargs: {"enable_thinking": false}`. Если переменная отсутствовала,
параметр не отправлялся для совместимости с другими провайдерами.
Механизм описан в [документации Qwen](https://qwen.readthedocs.io/en/v3.0/deployment/vllm.html)
и проверен реальными запросами к Alem. Это настройка данной модели, не гарантия
поддержки всеми совместимыми API.

Замеры трёх вопросов, последовательно, с чередованием режимов, тем же системным
промптом и лимитом 256 токенов. В системный промпт каждого запроса добавлялся
уникальный идентификатор для снижения влияния кэша. Это небольшая выборка,
не нагрузочный тест; идентификатор сам немного меняет вход модели.

| Режим | Время трёх запросов, с | Полные непустые ответы |
|---|---|---|
| Исходный | 5,837 / 2,496 / 7,561 | 1 из 3 |
| `/no_think` в промпте | 3,266 / 4,965 / 2,409 | 1 из 3 |
| `chat_template_kwargs.enable_thinking=false` | 0,856 / 1,217 / 0,612 | 3 из 3 |

Неуспешные ответы имели HTTP 200, но `content=null` и `finish_reason=length`:
лимит расходовался на рассуждения. В выбранном режиме поле рассуждений было
пустым, ответы завершались с `finish_reason=stop`, использовали 19–40 токенов
и соответствовали вопросам. Медиана времени всех запросов снизилась с 5,837
до 0,856 секунды, но исходный режим при этом не всегда давал пригодный ответ.

Первые замеры одинаковых запросов давали совпадающие ответы и расход токенов
даже при разных настройках, что похоже на кэширование у провайдера. Их нельзя
использовать как доказательство ускорения. Они сохранены отдельно от серии
с уникальными идентификаторами.

Результаты прежнего benchmark сохранены в игнорируемом Git файле
`recordings/qwen_benchmark_uncached.json`, включая только финальный текст,
время, расход токенов и длину рассуждений — без ключей и текста рассуждений.
Прежний скрипт перезаписывал результат предыдущего запуска. При смене модели или
нагрузки задержка может измениться. Потоковый ответ в текущем обычном диалоге
не реализован.

Повтор всей цепочки на исходном голосовом: STT — 2,358 с, Qwen — 0,325 с,
вся цепочка — 2,699 с. Поскольку запись и текст уже отправлялись ранее,
в этом повторе возможен вклад кэша; для оценки генерации используйте серию
с уникальными идентификаторами выше. Сервер перезапущен с новой настройкой.
