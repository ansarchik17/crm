# EspoCRM + VoiceCRM

Основная CRM проекта — **EspoCRM 10.0.9**: русский интерфейс, контакты, лиды,
компании, сделки, звонки, задачи, календарь, сотрудники и база знаний.
Голосовой помощник OpenAI работает отдельным FastAPI-сервисом с REST-адаптером
EspoCRM. Ядро используется из официального стабильного Docker-образа.

| Адрес | Назначение |
|---|---|
| http://localhost:8080 | Основной интерфейс EspoCRM |
| http://127.0.0.1:8001/ | Переход в основной интерфейс CRM |
| http://127.0.0.1:8001/voice | Alem → OpenAI → голос браузера |
| http://127.0.0.1:8001/realtime | Потоковый голосовой тест OpenAI Realtime |
| http://127.0.0.1:8001/crm/status | Живая проверка API-доступа к CRM |
| http://127.0.0.1:8001/docs | API голосового сервиса |

Вход: логин `admin`, случайный пароль сохранён локально в
`runtime/secrets/espo_admin_password`. API-ключ сервиса находится в исключённом
из Git `.env.espocrm`; его не нужно вводить в браузере или чате.
Оригинальный `.env` с OpenAI/Alem сохранён. Порты открыты только на localhost.

## Что подключено

- EspoCRM, постоянная MariaDB, фоновый обработчик и WebSocket уведомлений.
- Ограниченный API-пользователь: чтение контактов и справочника сотрудников,
  создание/чтение Call и Task. Изменение и удаление записей закрыты.
- Поиск по нормализованному телефону, включая форматированные номера.
  Несколько совпадений возвращаются без автоматического выбора.
- Подтверждение активности по ID, тайм-ауты и очищенные ошибки.
  Неподтверждённые POST не повторяются автоматически.
- Подтверждённая задача на обратный звонок в `/voice`: инструмент модели
  готовит черновик, клиент проверяет его и подтверждает кнопкой или точной
  фразой «Подтверждаю заявку». SQLite сохраняет операцию и результат;
  повтор одной операции не отправляет второй POST. Включение требует
  явного `CALLBACK_ASSIGNEE_ID`; по умолчанию сценарий отключён.
- При нескольких контактах клиент выбирает имя в форме; модель не выбирает
  его самостоятельно. Ответы callback без инструмента формируются из серверных
  шаблонов, сообщение об успехе — только по результату CRM.
- Голосовые API проверяют loopback/same-origin. Неактивные текстовые сессии
  истекают через 30 минут; журнал callback сохраняется независимо от них.
- Прежние голосовые режимы и восемь профилей агентов разработки.

Живые проверки используют явно помеченные синтетические записи.
Утверждённые знания, CRM-инструменты Realtime, медицинская запись, телефония,
запись аудио и анализ звонков остаются следующими этапами. Правила callback,
границы защиты от дублей и проверка — в [ESPOCRM.md](docs/ESPOCRM.md#обращение-на-обратный-звонок).

## Запуск

Нужен запущенный Docker Desktop. Из корня проекта:

```sh
.venv/bin/python scripts/prepare_espocrm.py
docker compose up -d --wait
.venv/bin/python scripts/bootstrap_espocrm.py
.venv/bin/python -m uvicorn voicecrm.main:app --host 127.0.0.1 --port 8001
```

Если Python-окружения нет, сначала `uv sync --locked`. Для CRM достаточно
Docker; Python нужен голосовому сервису. Существующий `.env` не заменяйте.
Подробности входа, настройки, повторного запуска и резервного копирования:
[docs/ESPOCRM.md](docs/ESPOCRM.md).

## Проверки

```sh
.venv/bin/python -m pytest -q
node --test tests/test_audio.mjs tests/test_realtime_events.mjs tests/test_callback_ui.mjs
docker compose config --quiet
```

Эти тесты не используют платные API. Настоящая локальная CRM проверяется так:

```sh
.venv/bin/python scripts/verify_espocrm.py
```

Проверяются API-роль, поиск, связанные Call/Task, запрет создания/удаления
контактов и закрытие внутренних файлов по HTTP. Тестовые записи помечены
`[ТЕСТ]`, успешные ID сохранены в `runtime/verification.json` для повторного
чтения без дублей. `/health` показывает конфигурацию; соединение проверяет
`/crm/status`.

## Структура и документация

```text
compose.yaml              EspoCRM + MariaDB + daemon + WebSocket
espocrm/                  код официального релиза для анализа
src/voicecrm/dialogue/    голосовой OpenAI/Alem и контекст
src/voicecrm/crm/         серверный REST-адаптер EspoCRM
src/voicecrm/static/      голосовые тестовые страницы
scripts/                  установка, bootstrap и проверки
agents/                   команда разработки
runtime/                  локальные секреты и результаты (не в Git)
docs/                     анализ, план и точка остановки
```

- [Анализ EspoCRM](docs/ESPOCRM_ANALYSIS.md): код, архитектура, API, права,
  сущности, расширения и ограничения.
- [Запуск](docs/ESPOCRM.md), [план](docs/ROADMAP.md),
  [точка остановки](docs/HANDOFF.md).
- [Realtime](docs/REALTIME.md), [Alem](docs/ALEM.md),
  [команда агентов](agents/README.md).

В `espocrm/` экспортирован официальный runnable release; рабочие данные и
vendor исключены. Это снимок для анализа, а не полный Git checkout для сборки:
происхождение указано в `espocrm/SOURCE.json`. Репозиторий —
[espocrm/espocrm](https://github.com/espocrm/espocrm),
[закреплённый релиз 10.0.9](https://github.com/espocrm/espocrm/releases/tag/10.0.9).
Повторный экспорт выполняет `scripts/export_espocrm_source.py`.
Расширения размещаются в custom/modules и устанавливаются отдельным пакетом.
Лицензия и обозначение EspoCRM сохранены.

До перехода сохранён код, тесты, документация и профили в
`data/backups/voicecrm-before-espocrm-20261013.tar.gz`; секреты исключены.
Прежний README сохранён как исторический [VOICE_SERVICE.md](docs/VOICE_SERVICE.md).
