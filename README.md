# VoiceCRM

Начало разработки голосового администратора: городской номер, до 30 внутренних
номеров, консультации, перевод сотрудникам, CRM, записи и анализ.

**Текущее состояние:** локальный прототип стоматологии с веб-страницей, записью
микрофона в WAV, файловым STT Alem, Qwen и озвучиванием голосами браузера.
Телефония, серверный TTS, CRM,
база знаний и аналитика ещё не реализованы. Название папки CRM не означает,
что здесь уже есть готовая CRM. Полный разбор: [docs/PROJECT.md](docs/PROJECT.md).

Настройка Alem Qwen и распознавание WAV: [docs/ALEM.md](docs/ALEM.md).
Адаптеры проверены с подменой HTTP и с реальными API Alem на локальных ключах.
Замеры задержки и настройка быстрого ответа описаны в [docs/ALEM.md](docs/ALEM.md).

Добавлен отдельный тест **OpenAI Realtime (голос → голос)** на
http://127.0.0.1:8000/realtime. Для него нужен `OPENAI_API_KEY` в локальном `.env`.
Код и локальные проверки готовы; живое подключение пока не проверено из-за
отсутствия ключа. Настройка, устройство и ограничения: [docs/REALTIME.md](docs/REALTIME.md).

## Тестовая стоматология

Для Qwen настроен сценарий администратора стоматологии: консультация, чистка,
лечение кариеса, удаление зуба, консультации по имплантации и брекетам.
Это учебные направления; реального прайса, клиники и расписания пока нет.
Помощник уточняет услугу, день и время, учитывает изменения пожеланий и сообщает,
что настоящая запись не создана. Медицинские назначения в сценарий не входят.

Ручная проверка на реальном API (6 запросов, возможна тарификация):

```sh
.venv/bin/python scripts/test_dental_dialogue.py
```

Скрипт использует две отдельные сессии, проверяет ответы на изменение дня,
вопрос о цене и попытку получить вымышленное подтверждение. Ответы нужно оценить
вручную; успешный HTTP-ответ сам по себе не означает корректный диалог.
После изменения системного промпта перезапустите уже работающий сервер.

## Запуск

Нужны Python 3.11+ и uv. Из папки проекта:

```sh
uv sync --locked
cp .env.example .env
uv run uvicorn voicecrm.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000/** для голосового теста.

1. Нажмите «Говорить» и разрешите браузеру доступ к микрофону.
2. Произнесите реплику и нажмите «Закончить запись» (автоостановка через 29 секунд).
3. Страница передаст WAV в Alem STT, затем текст — в Qwen в текущей сессии.
4. Ответ появится в переписке и будет озвучен выбранным голосом браузера.
   Если автоматическое воспроизведение не сработало, нажмите «Прослушать».

Можно писать текстом или загрузить поддерживаемый WAV. «Новый диалог» очищает
контекст. Для микрофона нужны localhost/HTTPS и браузер с AudioWorklet и записью
24 кГц; ошибка доступа не мешает текстовому режиму. Используйте вымышленные данные.
Голоса зависят от устройства; предпочтение отдаётся русскому локальному голосу.
Голоса «онлайн» могут отправлять текст своему поставщику. Отдельного TTS API-ключа
не требуется. Это диалог по очереди, не streaming: перебивания, телефонное аудио
и серверное создание озвученных файлов пока не реализованы. `/health` продолжает
возвращать `tts_connected=false`, поскольку серверного TTS нет.

Документация API: http://127.0.0.1:8000/docs. В режиме `demo` текстовые ответы
фиксированные и не требуют ключей; STT включается независимо. В текстовом демо
внешние запросы не нужны; это проверка сервиса, а не AI-консультация.

1. Выполните `POST /sessions`, скопируйте `session_id` из ответа.
2. Выполните `POST /sessions/{session_id}/messages` с телом
   `{"text":"Здравствуйте, хочу узнать об услуге"}`.
3. Отправьте вторую реплику с тем же идентификатором.
4. Завершите тест через `DELETE /sessions/{session_id}`.

## Подключение Qwen

В `.env` задайте `LLM_MODE=qwen`, `QWEN_BASE_URL`, `QWEN_MODEL`, `QWEN_API_KEY`,
затем перезапустите сервер. URL — адрес совместимого API до `/chat/completions`,
например с окончанием `/v1`; точное значение берётся у вашего провайдера.
В `.env.example` уже указаны адрес и модель из документации Alem.ai.
Для проверенной модели Alem `qwen3-8` настройка `QWEN_ENABLE_THINKING=false`
отключает внутренние рассуждения и сокращает ожидание короткого ответа.
Поддерживается текстовый Chat Completions без streaming. Совместимость вашего
endpoint и модели нужно подтвердить реальным запросом. Запросы могут тарифицироваться.

Ключ храните только локально в `.env`; он исключён из Git. Сервис не сохраняет
тексты на диск и не выводит ответы провайдера при ошибке. В режиме Qwen тексты
передаются выбранному провайдеру. Для проверки используйте вымышленные обращения.

## Проверки

```sh
uv run pytest -q
node --test tests/test_audio.mjs
```

Тесты не обращаются к платным API. Они проверяют контекст, разделение сессий,
удаление, ограничения, отказ провайдера и HTTP-контракт адаптера.

## Ограничения прототипа

- Только localhost, без авторизации; не публиковать в интернете.
- Один процесс: сессии в памяти, при перезапуске исчезают.
- До 100 сессий; ненужные удаляются вручную. До 20 реплик клиента на сессию.
- Один запрос на сессию одновременно; повтор получает 409.
- `/health` показывает состояние процесса, а не доступность внешнего AI.
- Инструкции модели не гарантируют достоверность ответов. До пилота нужны
  утверждённые знания, проверяемые действия и оценка качества.
- Замер `latency_ms` относится к текстовому ответу; это не задержка голосового диалога.

серверного TTS для телефонии и переход к потоковому диалогу.
