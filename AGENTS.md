# Команда разработки VoiceCRM

Общайтесь с пользователем на русском, простыми словами. Перед работой прочитайте
`docs/HANDOFF.md`, `docs/ROADMAP.md` и документацию затрагиваемого модуля.
Проверяйте текущий код: исторические проверки в документации не означают, что
функция уже работает сейчас.

## Назначение проекта

Основная CRM — EspoCRM 10.0.9 на http://localhost:8080, стек в `compose.yaml`.
Код официального собранного релиза находится в `espocrm/`; это снимок из image,
не dev checkout. Разбор — `docs/ESPOCRM_ANALYSIS.md`, запуск — `docs/ESPOCRM.md`.
Ядро Espo не меняйте: расширяйте через custom/modules, metadata и REST.
Голосовой FastAPI на 8001: `/` перенаправляет в EspoCRM, `/voice` использует
Alem STT → текстовый OpenAI → браузерный SpeechSynthesis; `/realtime` —
OpenAI Realtime через WebRTC. Qwen удалён; не возвращайте его без запроса.
CRM-адаптер поддерживает поиск контактов и серверные Call/Task, но автоматические
действия голосового диалога, outbox, телефония и аналитика требуют реализации.
CRM хранит KnowledgeBaseArticle; утверждённые знания компании ещё не загружены.

## Делегирование

Профили команды находятся в `agents/profiles/`, рабочие копии — в
`.codex/agents/`. Координатор назначает агенту конкретную задачу и файлы.
Один файл одновременно изменяет один агент; смежные изменения согласовывайте.
Количество параллельных агентов ограничено текущей средой, а не числом профилей.

| Профиль | Основная область |
|---|---|
| `crm_architect` | Архитектура, этапы, контракты между модулями |
| `voice_backend` | FastAPI, OpenAI, STT, настройки и сессии |
| `realtime_audio` | Браузерное аудио, WebRTC, VAD и перебивания |
| `latency_qa` | Замеры скорости, регрессии и качество разговора |
| `crm_integrations` | Адаптер CRM, подтверждённые операции и повторы |
| `telephony_engineer` | SIP, Asterisk/ARI, маршрутизация и перевод |
| `call_analytics` | Записи, расшифровка и анализ звонков |
| `knowledge_quality` | Знания компании и достоверность диалогов |

## Правила работы

- Репозиторий пользователя: `https://github.com/ansarchik17/crm.git`.
  После каждой реализованной задачи запускайте относящиеся к ней проверки,
  делайте отдельный коммит и сразу push. Сохраняйте существующую историю;
  секреты, runtime-данные и записи в Git не добавляйте.
  По просьбе пользователя не добавляйте Claude в соавторы коммитов.
- Сохраняйте существующие незакоммиченные изменения. Не перезапускайте чужие
  процессы: перед управлением сервером проверьте PID и рабочую папку. CRM здесь
  использует порт 8001, EspoCRM — 8080, уведомления — 8083. Порт 8000 занят
  другим проектом. Управляйте только Compose-проектом `voicecrm-espo`.
- Не выводите `.env`, `.env.espocrm`, `runtime/secrets`, API-ключи, реальные
  записи и персональные данные. Не удаляйте Docker volumes с CRM-данными.
  Долговременный OpenAI-ключ используется только сервером.
- Проверяйте API по актуальным официальным источникам. Передача задачи другому
  агенту не расширяет разрешения среды и авторизацию пользователя.
- Координатор организует живые проверки API и микрофона; агенты не дублируют
  платные вызовы. Локальные тесты используют синтетические данные и HTTP-подмену.
- Подтверждение записи, заявки и перевода должно следовать из результата
  соответствующей системы. Текст модели не является подтверждением операции.
- API-пользователь Espo читает контакты и ограниченный справочник сотрудников,
  создаёт/читает Call/Task. У него нет admin, edit/delete/export. Неподтверждённый
  POST не повторяйте без сверки: запись могла сохраниться. Calendar/Meeting сами
  по себе не доказывают свободное время или запись на медицинский приём.

## Приёмка скорости и качества

Цель: около одной секунды от конца речи до первого слышимого ответа. Она пока
не подтверждена живой проверкой Realtime. Текущий таймер Realtime измеряет
получение `speech_stopped` → получение `output_audio_buffer.started`: он не
включает VAD-паузу и физическое воспроизведение. Называйте его «отклик сервиса».
Для полного замера указывайте границы, размер выборки, p50/p95, ошибки и
неуспешные ответы. Короткое подтверждение начала работы не означает завершения CRM.

При снижении VAD проверяйте паузы внутри фразы, перебивания, поздние события,
молчание и сохранение последних пожеланий клиента. Используйте новые реплики;
повтор одного файла может искажать оценку из-за кэша.

После изменений запускайте относящиеся к ним проверки. Перед итоговой передачей
изменений голосового диалога выполните:

```sh
.venv/bin/python -m pytest -q
node --test tests/test_audio.mjs tests/test_realtime_events.mjs
git diff --check
```

Отчёт агента: что изменено, какие файлы затронуты, что проверено, что осталось.
Обновляйте актуальную точку остановки в `docs/HANDOFF.md`.
